# Evals Demo

This project measures whether the `com.jamesward:skills:0.0.3`
`zen-of-james` skill changes code generated by the same model.

The eval runs two isolated arms:

- **A:** model only, with no inherited skills, steering, web, or MCP tools.
- **B:** the same model and task with the classpath `zen-of-james` skill
  explicitly invoked.

The task asks for a Scala 3 / ZIO 2 order-intake implementation with separate
direct pure parser/domain tests and effectful service tests using fakes. A strict
hidden rubric and deterministic checks grade the output against the skill's
principles: illegal states unrepresentable, domain types, parse-don't-validate,
closed ADTs, immutability, effects as values, resource safety, and test onions
using `assertTrue`. The program exits unsuccessfully unless A fails and B passes.

## Develop against the sibling zio-evals checkout

The skills API is currently in `../zio-evals`:

```bash
./sbt -Dlocal compile
./sbt -Dlocal run
```

Without `-Dlocal`, the build uses the published
`com.jamesward:zio-evals_3:0.0.3` release.

## Runtime options

Kiro is the default backend and uses the operator's default model:

```bash
./sbt -Dlocal run
```

Claude Code can be selected explicitly:

```bash
./sbt -Dlocal \
  -Deval.backend=claude \
  -Deval.model=claude-sonnet-4-6 \
  -Deval.maxBudgetUsd=1.00 \
  run
```

Use `-Deval.samples=5` for a less noisy final comparison. One sample requires
three model calls: baseline, treatment, and judge.

Both backends use fresh temporary workspaces. Kiro disables inherited default
resources and loads only the treatment skill as a `file://` context resource.
Claude loads project settings only for the treatment and grants only
`Skill(zen-of-james)`. Baseline and judge runs therefore do not require the
user's global skill to be disabled.
